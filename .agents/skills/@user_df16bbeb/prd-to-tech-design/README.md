# prd-to-tech-design

> 根据 PRD 文档结合存量项目代码生成技术设计文档

[![version](https://img.shields.io/badge/version-0.0.2-blue.svg)](https://github.com)
[![author](https://img.shields.io/badge/author-hejie38-green.svg)](https://github.com)

## 简介

`prd-to-tech-design` 是一个  Agent Skill，能够将 PRD（产品需求文档）自动转换为可执行的技术设计文档。

**核心特点**：
- 📖 **PRD 解读**：精准提取核心需求、边界条件、异常场景
- 🔍 **代码分析**：扫描存量代码，识别技术栈、公共组件、已有接口/表结构
- 📝 **文档生成**：输出符合项目规范的技术设计文档
- ⚠️ **主动澄清**：遇到模糊点主动询问，不臆造

## 安装

```bash
# 从本地路径安装
npx @jd/skills install .ai/skills/prd-to-tech-design

# 或从指定目录安装
npx @jd/skills install /path/to/prd-to-tech-design
```

## 使用方法

### 基本用法

在 JoyCode 中直接对话：

```
根据这个 PRD 生成技术设计文档：
[粘贴你的 PRD 内容或提供链接]
```

### 支持的输入形式

| 形式 | 说明 |
|-----|------|
| URL 链接 | PRD Joyspace文档链接 |
| 直接粘贴 | 在对话中直接粘贴 PRD 文本 |

### 工作流程

```
1. 获取 PRD → 2. 确认扫描范围 → 3. 选择模板
      ↓              ↓                ↓
4. 分析代码 → 5. 解读 PRD → 6. 澄清模糊点
                              ↓
                        7. 生成文档
```

## 文档模板

| 模板 | 适用场景 | 包含章节 |
|-----|---------|---------|
| **精简模板** | 简单需求（<3个接口） | 需求概述、核心接口、数据库变更、风险点 |
| **标准模板** ⭐ | 大部分需求（默认） | 需求概述、架构设计、接口设计、数据库设计、非功能需求、风险点、排期 |
| **详细模板** | 复杂需求（>10个接口） | 标准模板 + 时序图、流程图、状态机设计 |

## 核心约束

1. **代码优先原则**：所有技术决策必须基于存量代码分析
2. **技术栈对齐**：使用项目已有的技术栈和框架
3. **规范统一**：遵循项目现有的编码规范和设计模式
4. **主动澄清**：遇到模糊点主动询问用户，不臆造
5. **可编码性**：输出的设计必须能直接指导开发实现

## 输出示例

生成的文档默认保存到 `docs/tech-design/` 目录：

```
docs/tech-design/
└── tech-design-[需求名称]-[YYYYMMDD].md
```

文档包含：
- 文档元信息（需求名称、PRD来源、技术栈等）
- 需求概述（背景、核心功能、影响范围）
- 澄清记录（生成前的问答记录）
- 架构设计（架构图、模块划分、技术选型）
- 接口设计（接口列表、请求响应参数、调用关系）
- 数据库设计（表结构、索引、迁移方案）
- 非功能需求（性能、安全、可用性）
- 风险点与待确认项
- 开发排期

## 配置项

| 配置项 | 默认值 | 说明 |
|-------|--------|------|
| 扫描范围 | 自动识别 | 指定模块 / 自动识别 / 全工程扫描 |
| 文档模板 | 标准模板 | 精简 / 标准 / 详细 |
| 输出目录 | docs/tech-design/ | 文档保存路径 |
