# 模块还原核对清单

每完成一个模块（阶段 3）就过一遍这份清单。目标不是追求完美，而是抓住"跳过对比"必然出现的系统性漂移。

## 准备工作

需要并排放两样东西：
1. **参考图**——从 MCP 拉的 2x 渲染 PNG，已经存在本地
2. **你的产物**——和参考图同宽度的渲染结果（浏览器、artifact 预览，或 devtools 截图）

如果产物本身不好直接渲染（比如小程序文件），就在开发工具里按目标宽度截图。如果连开发者工具都跑不起来（在 artifact 里写的不能直接预览），按 SKILL.md 阶段 3 的"D：纯静态对比"路径——把 CSS 值和参考图能读到的对照看一遍。

## 怎么用这份清单

每条核对结果分两档：

- ❌ **必修差异**——当下修，不能带进下一个模块。包括：
  - 颜色错（用了 token 之外的值，或用错了 token）
  - 布局结构错（flex 方向、wrap 行为、对齐方式不对）
  - 组件用错（应该用现有组件库的却自建了，或反之）
  - 字号差超过 2px
  - 间距差超过 4px
  - 元素缺失或多余

- 📝 **可记录差异**——写到模块文件顶部 `// FIDELITY-NOTES:` 注释里，最后阶段 4 汇总。包括：
  - 字间距 0.5px 以内的微调
  - 阴影颜色 / 透明度的微差
  - 圆角差 1px 以内
  - 渐变中间色相差不到 5%

如果某条核对触发了"必修"档，**当下停下修复**，不要走完整个清单再回头。

## 布局

- [ ] **容器宽度**在目标视口下一致
- [ ] **Flex / Grid 方向一致**（行/列、是否换行）
- [ ] **对齐方式一致**（justify-content、align-items）——常见漂移：把 justify-between 写成 flex-start
- [ ] **同级元素之间的 gap / 间距一致**，误差不超过 ±2px
- [ ] **容器内 padding 一致**，误差不超过 ±2px
- [ ] **元素顺序一致**（LTR 设计一般没事，但 RTL 或特殊顺序容易反过来）

## 字体排印

- [ ] **字体族一致**——如果设计用了非系统字体，fallback 也要写
- [ ] **字号精确一致**——从 MCP 读，不要肉眼估
- [ ] **字重一致**（400/500/600/700——设计师常用 500，开发常默认 400）
- [ ] **行高一致**——这是垂直漂移的最大单一来源
- [ ] **字间距一致**（如果设计稿有指定）
- [ ] **文字颜色用了对应 token**，不是某个游离的 hex
- [ ] **截断行为一致**——如果设计有省略号或多行裁剪，要还原

## 颜色与填充

- [ ] **背景色用 token 调色板里的值**——如果你写的 hex 和某个 token 接近但不完全相等，那它大概率应该就是那个 token
- [ ] **边框用对了 token**——正文边框、分隔线、聚焦环通常是不同的 token
- [ ] **渐变方向和色标点一致**——渐变很容易出错，多看一眼
- [ ] **不透明度一致**——设计稿里的提示文本常用 rgba 或 opacity，纯 hex 对不上

## 图标与素材

- [ ] **图标尺寸正确**
- [ ] **图标颜色正确**（一般用 `currentColor` 而不是写死颜色）
- [ ] **图片正确加载、没有被裁切**——`object-fit` 是常见漂移源
- [ ] **SVG 素材能直出就直出**——MCP 能导出就用导出，不要重画

## 状态（如果在范围内）

- [ ] **Hover 态**符合设计指定
- [ ] **Active / 按下态**正确
- [ ] **Disabled 态**有正确的透明度 / 灰色 token
- [ ] **聚焦环**可见，并且用了 focus token

## 响应式（如果有多个视口）

- [ ] **每个断点的渲染都对得上**
- [ ] **任意中间宽度都不溢出**
- [ ] **字号按设计稿缩放**，不是浏览器默认

## 差异比较大时

如果一遍跑下来差距明显：

1. **先查 token**——颜色 token 或字体 token 用错了，整体就会"哪里不对劲"
2. **再查间距**——padding/gap 不对会让整个布局感觉变了，即使每个元素都对
3. **最后查字体**——行高和字重的差异虽然细，但会让文本块感觉变胖或变高

如果两遍下来还是收敛不了，停下，告诉用户哪里漂移、漂在哪——别带着已知问题交付。
